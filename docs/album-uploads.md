# Private album ingestion

The performer console's Upload album audio panel accepts a real MP3 or WAV for an existing unplayed source. It does not seed songs or call a generation provider. It fully decodes a five-second to ten-minute mono/stereo song, strips metadata, creates a 192 kbps MP3 playback derivative, validates duration/silence, verifies private object storage and updates only the source's audio URL and measured duration. Title and core prompt are preserved. The original input is NOT retained remotely; the artist must keep the master. Inputs are limited to 128 MiB and processing is limited to one upload at a time per API process. Deployment hardware may impose lower practical time/memory limits; test actual files before a show.

Private storage is the same S3-compatible MediaStore as generated releases; Neon Object Storage can provide that endpoint. With no store configured, the server rejects the upload before consuming its body and the UI disables file selection. No bucket or credentials are provisioned by source code. A free storage allocation is not a license to incur overages; retain the owner's $0 limit and provider-side free-plan limits.

POST /api/operator/sources/:id/upload uses binary application/octet-stream with X-Command-Id and X-Event-Revision. The server requires the owning artist's HttpOnly session and exact Origin before reading audio. It checks ownership, a revision fence, source immutability, a digest-bound command replay, complete decoder validation and the same conditions again before publication. The owning event is locked while writing the final private object and attaching the file, preventing concurrent round startup from observing a replacement midway through. Failed validation never changes the source. The app never follows URLs found inside an uploaded file.

The durable source URL is the stable authenticated /api/operator/sources/:id/audio/:sha route. It confirms the requesting artist owns the source and the SHA identifies its current active file, then issues a short-lived storage URL. Expiring signed URLs are never saved as album source identities. Public listeners and native guest credentials cannot retrieve unpublished album audio. Replacing a track leaves its previous private object for explicit storage cleanup; no automatic deletion is performed. A storage success followed by a database failure may leave a private content-addressed orphan; retry uses the same key, and orphan cleanup must compare active source routes before deletion.

No schema migration is necessary: source_tracks.audio_url stores the stable content-addressed route and source_tracks.duration_seconds stores the rounded-up measured duration. Responses retain the precise measured duration and output SHA. Rollback to a server without the delivery route breaks uploaded album playback, so preserve that route or export/replace audio links before reverting. Source edits and round immutability remain unchanged.

Automated tests use isolated audio fixtures and private in-memory storage, not seeded production content. Required acceptance includes real Neon bucket upload/download checks, private-route checks on the deployed origin, and actual artist file/device playback. Passing CI alone is not that evidence.
