# Artist review and publication controls

Show settings offer three release policies: the next track boundary (default), as soon as ready, or artist review. The setting is copied into each new round and frozen into its generation job. Changing the show setting does not silently change an active round or existing job. Artist review creates a publication hold before dispatch; it also applies to artist-supplied assets and survives the end of the set.

Each unpublished generation has **Hold publication** or **Allow automatic release**. A hold can be set while provider work is running. It changes publication only: it does not recall a provider request, promise a refund or reopen voting. Removing a hold allows the next boundary; an ended show or an immediate-policy job publishes its ready result at once. A ready visible result also offers **Publish to everyone now**, which explicitly approves publication immediately. A review-policy job whose hold is removed behaves like boundary release while the show is live.

**Cancel unsent generation** is limited to queued or blocked work with zero attempts, zero reserved cost and no attached release. Cancellation and dispatch lock the same event and job. If dispatch wins, cancellation is rejected. Cancelled jobs retain their prompt snapshot and participation history and cannot be resumed or receive a replacement asset through the existing manual attachment endpoint. Their job still counts toward the show's generation limit. Unknown and in-flight work remains reserved against the approved budget and is never automatically retried.

All controls require the owning artist's operator session, exact browser Origin and a unique command ID. Replaying a successful command returns its original result without a second publication or audit entry. Published music cannot be put back on a pre-publication hold: use moderation to hide it. Approval never restores a hidden result automatically.

The operator snapshot includes held state and an unpublished release ID. Public snapshots omit those fields and all private preview links. An artist can preview ready unpublished music through an authenticated, artist-scoped media route; that preview does not increment public listening counts. Hidden music is unavailable there. Signed storage URLs are short lived but cannot be recalled once issued. Artist-supplied HTTPS files remain subject to the external host's access policy; this feature cannot make an already-public external URL private. Public catalog, downloads, credits and email fanout continue to require a visible published release.

Migration 006 adds publication flags/policy and the cancelled job state without changing stored audio or snapshots. Readiness requires migrations 001–006. Rehearse on the isolated development branch. During rollout stop old workers and prevent old application instances from advancing boundaries before enabling holds: earlier code does not understand publication holds. Rollback requires keeping workers stopped and resolving held/unpublished work before restoring earlier boundary logic. Do not delete generations or remove holds as an automated rollback shortcut.

Verification includes cancellation before dispatch, rejected cancellation after dispatch, a hold while a provider response is pending, retained cost, end-of-show review holds, boundary enforcement, hidden-release exclusion, operator/guest isolation and exactly-once explicit publication. Providers and media storage in these tests are fixtures. Browser coverage exercises configuring review, attaching an artist-supplied result, preview controls and explicit approval; physical headphones and real provider/storage acceptance remain separate gates.
