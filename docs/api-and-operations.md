# API and operational handoff

The application is a shared PostgreSQL-backed multiplayer service. It never falls back to in-memory production state. Node.js 24 and npm are required.

## Local work

Run `npm ci`. Copy `.env.example` to `.env.local` and configure the development database. Run `npm run db:migrate`, `npm run build:server`, then `node --env-file=.env.local dist/server/apps/api/src/main.js`. Run `npm run check` for typecheck and tests. Tests use isolated embedded PostgreSQL unless `TEST_DATABASE_URL` explicitly points to an integration branch. Never point tests at production.

Migrations are versioned, transactional, and serialized through their ledger. The initial DDL parser supports simple statements without semicolons inside literals/functions. A migration introducing functions must first upgrade the runner.

## HTTP contracts

Mutations must carry the exact Origin configured as PUBLIC_ORIGIN. Requests are JSON, authenticated with HttpOnly cookies. POST /api/session creates a guest identity; PATCH /api/profile updates alias/anonymity. POST /api/events/:slug/join joins. GET /api/events/:slug returns the public snapshot with the guest's current allocation and revision. GET /api/events/:slug/stream sends SSE invalidations; reconnect obtains a full snapshot.

POST /api/rounds/:id/waves accepts commandId, text, expectedRevision and optional moveFrom. A submission consumes one of five points. moveFrom atomically moves an existing point. Exact duplicates support the original author. PUT /api/rounds/:id/allocations accepts commandId, expectedRevision and a complete allocations map. Omitted waves lose that participant's points. Conflict responses require a refresh, not blind replay.

POST /api/operator/login exchanges a configured operator bootstrap token for a 12-hour session scoped to our-jam. This initial single-artist workflow does not complete multi-artist/account identity. Login is disabled without a strong configured token. POST /api/operator/logout revokes the session. Never put credentials in URLs, client bundles or localStorage.

Operator routes create events, advance playback, insert releases next, remove queued items, hide waves and attach an artist-verified external asset. Supplied assets are labeled artist_supplied_asset, never represented as provider-generated by this app. Public routes exclude core prompts and unpublished URLs.

Reactions are mutable -1/0/+1; dislikes are private to the performer. Comments are plain text, reportable and removable by their author. Listening intervals merge and are bounded. Counts are client-reported telemetry, not proof of attention. Private previews send no audience telemetry.

## Durability and concurrency

Transactions lock event then round. Revisions prevent double spending across tabs. Closing writes a unique generation job and immutable prompt/selection snapshot. Provider calls never occur in this transaction. SSE follows the committed event log with at-least-once delivery. Queue revision changes on playback/queue operations, not on each vote.

## Remaining release gates

These endpoints do not establish automatic provider generation, durable media ownership, email/push, verified human identity, a recording route, native store delivery or venue readiness. Free Render instances may sleep. Original acceptance criteria remain authoritative.
