# Audience, display and performer client

Routes: `/` event discovery; `/event/:slug` phone-first participation, listening, feedback and profiles; `/screen/:slug` read-only venue display and QR entry; `/performer` operator sign-in/event setup; `/performer/:slug` show console.

The audience joins with an HttpOnly guest session. Five visible points correspond to server allocations. Plus/minus and submission commands carry a revision and unique ID; stale actions refresh rather than secretly replaying. The visual field takes the server's ranked waves. Three.js shader spheres and orbiting wave rings have independent movement. Reduced-motion users receive a static visual field. Lack of WebGL falls back to the same ranked labels and lightweight artwork.

The performer can configure tracks, core prompts, durations and screen limits; open the read-only display; manually advance rounds; optionally advance at HTML audio end; see release plays/reactions; privately preview; and insert a release next. The initial player explicitly warns that pause does not yet extend voting. Playback ownership, pause/recovery, caching and real audio input analysis remain the next safety slice.

The initial browser microphone recorder is a local, in-memory recording and user download. It is not recovery-safe and does not automatically capture Rave microphones. This partial feature does not complete P022. Local persistent chunk capture must be added before recording can be relied on.

PWA manifest and responsive browser routes are implemented. Service-worker/offline audio and native iOS/Android delivery remain outstanding. Local browser installation failed because the browser archive could not be retrieved; GitHub CI supplies the browser acceptance gate. No real-device compatibility or visual QA claim is made before corresponding evidence is reviewed.
