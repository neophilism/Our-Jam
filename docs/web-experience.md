# Audience, display and performer client

Routes: `/` event discovery; `/event/:slug` phone-first participation, listening, feedback and profiles; `/screen/:slug` read-only venue display and QR entry; `/performer` operator sign-in/event setup; `/performer/:slug` show console.

The audience joins with an HttpOnly guest session. Five visible points correspond to server allocations. Plus/minus and submission commands carry a revision and unique ID; stale actions refresh rather than secretly replaying. The visual field takes the server's ranked waves. Three.js shader spheres and orbiting wave rings have independent movement. Reduced-motion users receive a static visual field. Lack of WebGL falls back to the same ranked labels and lightweight artwork.

The performer can configure tracks, core prompts, durations and screen limits; open the read-only display; manually advance rounds; optionally advance at HTML audio end; see release plays/reactions; privately preview; and insert a release next. The player now has a fenced controller lease, pause/resume, deadline recovery, and paused startup until linked audio begins. Audio caching and stage input analysis remain outstanding.

The browser recorder saves checksummed chunks and a manifest in IndexedDB, with reload recovery and export. It does not automatically capture Rave microphones. Full-show capture, real-device interruption tests, input routing and encrypted upload remain required to complete P022. See playback-and-recovery.md.
